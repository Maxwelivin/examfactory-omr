# 已知限制與待改善項目（Phase 1 結束時）

## 尚未驗證

- **沒有任何真實拍攝照片的測試結果**。所有準確度證據都來自合成影像；門檻（塗黑 0.30、空白 0.12、模糊 1.5 mm）需用真實照片校正。
- 沒有在 iPhone / Android 實機上跑過。手機上的載入時間、記憶體、辨識速度未知。
- 列印對話框的實際輸出（各瀏覽器、各印表機）未實測。

## 功能限制

- 只支援單選 A–D、10/20/30/40/50 題。
- 只能拍照或選照片，尚無即時相機掃描（Phase 2）。
- 尚未做成 PWA，**目前無法離線**：第一次開啟要連線下載約 15.6 MB 的 OpenCV.js，且沒有 Service Worker 快取（Phase 3）。
- 姓名欄只裁切成圖片，不做手寫辨識；座號可用劃記或手動輸入。
- 沒有班級名單；姓名要手動輸入（或只用座號）。
- 重複掃描防護目前是「同座號」與「畫記指紋 ≥ 95% 相同」兩種提醒，仍由教師決定是否取代。
- 修改考試答案或配分後，已掃描的成績會自動重算；但修改題數不支援（請新建考試）。

## 辨識的已知弱點

- 原子筆、螢光筆、紅筆畫記：亮度/色彩與鉛筆不同，未測試；灰階後可能偏淡 → 多半變成待確認，而不是讀錯。
- 學生在圓圈外打勾、畫叉、寫字：只取圓圈內 60%，圈外的痕跡不影響，但打勾穿過圓心會被讀成淡畫記（待確認）。
- 嚴重彎曲或摺痕：透視轉換假設紙張是平面，紙張拱起時中央的格子會偏移。答案區 5.5 mm 圓圈、取樣半徑 1.65 mm，可容許約 1 mm 偏移。
- 四角黑塊被手指、陰影大面積覆蓋或裁切時會拒收（設計上寧可拒收）。
- 照片過曝（紙張 ≥ 238 灰階）時無法偵測反光。
- 只用單張影像判斷；Phase 2 的連續掃描可以多幀比對提高穩定度。

## 瀏覽器限制與替代方案

| 限制 | 說明 | 替代 |
|---|---|---|
| 相機需要 HTTPS | `getUserMedia`（Phase 2 即時掃描）只能在 HTTPS 或 localhost 使用 | Phase 1 用 `<input capture>`，HTTP 區網也能拍照；Phase 2 用 Vite basic-ssl 或部署到 GitHub Pages |
| iOS 清除資料 | Safari 對未加入主畫面的網站，7 天沒開可能清除 IndexedDB | 加入主畫面、`navigator.storage.persist()`、定期備份 |
| HEIC 照片 | 電腦版 Chrome 無法解碼 iPhone 的 HEIC | 手機上傳時 iOS 會自動轉 JPEG；或相機設定「最相容」 |
| 列印縮放 | 瀏覽器可能自動縮放 | 引擎以定位點校正，等比例縮放不影響 |
| 大型 WebAssembly | OpenCV.js 約 15.6 MB，首次載入慢 | Phase 3 以 Service Worker 快取；之後可考慮自行編譯精簡版 OpenCV.js（只含用到的模組） |

## 下一步（Phase 2 起）

1. 先收集真實照片做第 3 層測試，校正門檻（**這比開發新功能更重要**）。
2. 即時相機：getUserMedia、取景框、即時定位點提示、穩定與清晰度檢查後自動擷取、聲音/震動提示、暫停/繼續、連續掃描防重複。
3. PWA：manifest、Service Worker 預先快取（含 OpenCV wasm）、離線就緒狀態、更新提示。
