# OMR 辨識演算法說明

程式：`src/omr/engine.ts`（影像處理）、`src/omr/classify.ts`（判讀規則）、`src/omr/layout.ts`（座標規格）。
瀏覽器在 Web Worker 中執行，Node 測試直接呼叫同一個 `recognize()`。

## 0. 座標系

答案卡上每個元素都以 **mm** 定義在 `layout.ts`。辨識時把照片校正成「每 mm 5 像素」的標準影像（1050 × 1485 px），
因此任何元素的像素位置 = mm 座標 × 5，與照片解析度、拍攝距離無關。

## 1. 定位標記偵測（Step 2）

1. 照片轉灰階，縮到長邊 1000 px（加速）。
2. 5×5 高斯模糊 → **自適應二值化**（區塊 ≈ 長邊/12，C=12）。自適應閾值比全域閾值更能抵抗陰影。
3. `findContours(RETR_LIST)` 取所有輪廓（不能用 RETR_EXTERNAL：深色桌面會把紙張包成「洞」，裡面的方塊會被丟掉）。
4. 每個輪廓要同時通過：
   - 面積在 (0.6% 長邊)² 到 (10% 長邊)² 之間；
   - 最小外接矩形長寬比 ≤ 1.8；
   - **填滿率**（輪廓面積 ÷ 外接矩形面積）≥ 0.86 — 正方形約 1.0，已塗的圓圈約 0.785，會被排除；
   - 多邊形近似為 4–5 個頂點；
   - **實心檢查**：中心區平均灰階 < 外圍環帶的 60%，且差距 > 40 — 排除空心框（姓名欄等）。
5. 從前 20 個候選中窮舉 4 個的組合，要求：凸四邊形、對邊長度比 ≤ 2、長短邊比在 1.468 ± 35% 內
   （定位點中心距 273 mm ÷ 186 mm）、方塊大小與四邊形尺寸相符、四個方塊面積比 ≤ 3。取面積最大者。
6. 依短邊方向排出 TL→TR→BR→BL。這一步可以處理手機直拿、橫拿，但無法分辨 0° 與 180°（見第 3 步）。

## 2. 透視校正（Step 3–4）

四個方塊中心（原圖座標）對應到 `layout.ts` 的四個中心（mm × 5），
用 `getPerspectiveTransform` 求 3×3 單應矩陣 H：

```
[x' y' w]ᵀ = H · [x y 1]ᵀ，標準座標 = (x'/w, y'/w)
```

四組對應點正好決定 8 個自由度。以 `warpPerspective`（雙線性內插、邊界填白）在**全解析度灰階**上取樣，得到標準影像。
因為使用的是相對位置，印表機等比例縮放、影印縮小都不影響。

## 3. 方向判定與自我檢查

- 識別碼條 22 格：第 1 格恆黑、最後一格恆白，中間 16 位資料 + 4 位 CRC-4/ITU。
  先以正向讀取；若 CRC 不符，將標準影像旋轉 180° 再讀。哪個方向 CRC 正確就採用哪個。
  倒置的讀值因起止格互換必定失敗（單元測試以 675 個代碼驗證）。
- 校正後四角必須是黑色（< 紙張亮度 60%），否則視為誤認，要求重拍。
- 兩個方向都讀不到識別碼時：照常辨識（假設正向），但加上警告，請教師核對。

## 4. 光照正規化（Step 5）

對標準影像做 41×41（約 8 mm）的**灰階膨脹**（取局部最大值）：塗黑的圓圈（5.5 mm）比核小，會被周圍白紙「填掉」，
得到的就是每個位置的紙張亮度 B(x,y)。再以 σ=12 px 高斯平滑。每個像素的暗度：

```
d(x,y) = clamp(1 − I(x,y) / B(x,y), 0, 1)
```

陰影、光照漸層會同時壓低 I 與 B，比值不變，因此不需要全域二值化。

## 5. 畫記取樣（Step 6–7）

- 每個圓圈只取**半徑 60%** 以內的像素（印刷外框在半徑 100%，0.3 mm 線寬）— 外框不會被算進畫記。
- 畫記程度 = 內圈平均暗度。
- **紙張基線**：該張答案卡所有作答圓圈畫記程度的中位數（大部分圓圈是空白），每個分數都減去基線。
  這可以抵消紙張顏色、影印底灰、殘留色調。
- 反光：若紙張本身未過曝（第 90 百分位 < 238），圓圈內 ≥ 252 的像素比例超過 25% 視為反光，該題待確認。

## 6. 判讀規則（Step 8，`classify.ts`）

令 s₁ ≥ s₂ 為最深與第二深的分數，M = 塗黑門檻（預設 0.30），Bk = 空白門檻（0.12）：

| 條件 | 判定 |
|---|---|
| 有反光 | 待確認 |
| 兩個以上 ≥ M，且 s₂ ≥ 0.6·s₁ | 複選 |
| 兩個以上 ≥ M，但 s₂ < 0.6·s₁ | 待確認（可能擦除不完全） |
| 恰一個 ≥ M，s₂ < Bk | 答案 |
| 恰一個 ≥ M，Bk ≤ s₂ ≤ 0.5·s₁ | 答案（附註：其他選項有淡痕） |
| 恰一個 ≥ M，s₂ > 0.5·s₁ | 待確認 |
| 全部 < Bk | 空白 |
| 最深者介於 Bk 與 M | 待確認（畫記太淡） |

原則：**不猜測**。任何模糊地帶都標為待確認，由教師在畫面上修正；待確認題不計分，整張狀態為「待確認」。
所有門檻可在「設定」調整，分數保存在紀錄中，教師可在結果畫面開啟「顯示畫記分數」核對。

座號用同一套規則（十位、個位各 10 選 1）。十位空白視為 0。

## 7. 品質檢查

| 項目 | 方法 | 處理 |
|---|---|---|
| 找不到四個定位點 | 候選 < 4 或沒有合格四邊形 | 拒收，提示完整入鏡 |
| 模糊 | 識別碼黑格上緣 20%→80% 亮度過渡寬度（mm） | > 1.5 mm 拒收；> 0.9 mm 警告 |
| 太小 | 定位點在原圖 < 14 px | 警告 |
| 太暗 | 紙張亮度中位數 < 90 | 警告 |
| 反光 | 見第 5 節 | 該題待確認＋警告 |

模糊指標的選擇：最初用拉普拉斯變異數，但它被雜訊主導，與實際模糊程度不單調（σ=2 px 已低於門檻，但判讀全對）。
改用印刷邊緣寬度後，量測值與高斯模糊 σ 的理論關係（20–80% 寬 ≈ 1.68σ）吻合：

| 合成模糊 σ（照片 px，約 5.7 px/mm） | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 量得邊緣寬度（mm） | 0.2 | 0.4 | 0.6 | 0.8 | 1.2 | 1.6 | 1.8 |
| 完全塗滿的答案判讀 | 全對 | 全對 | 全對 | 全對 | 全對 | 全對 | 全對 |

完全塗滿的答案在很模糊時仍讀得對，但淡色畫記與擦除殘影會隨模糊失真，所以門檻刻意設在 1.5 mm。
**這組門檻來自合成影像，需要真實照片校正**（見 TESTING.md）。

## 8. 效能

Node（Windows 桌機）上，1500×2000 照片單張約 0.7 秒（含 Worker 外的影像解碼不計）。手機效能尚未實測。
