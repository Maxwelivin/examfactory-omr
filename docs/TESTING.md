# 測試說明

測試分三層，**合成影像與真實影像嚴格分開**。

## 1. 單元測試＋合成影像測試（自動）

```powershell
npm test
```

- `tests/unit.test.ts`（19 項）：識別碼編解碼與 CRC、版型幾何、判讀規則、計分、CSV。
- `tests/engine.synthetic.test.ts`（23 項）：用 `sheetSvg()` 產生答案卡 → resvg 點陣化 → 模擬鉛筆畫記 → 投影到桌面 → 加光照、陰影、模糊、雜訊、反光，再跑辨識引擎。

合成影像的產生器在 `tests/synthetic/synth.ts`。`npm run synth` 會輸出幾張樣張到 `tests/synthetic/out/` 供目視或手動上傳測試。

| 類別 | 合成案例 | 預期 |
|---|---|---|
| 正常畫記 | 20 題、50 題、偏一側部分塗滿 | 逐題正確、座號、識別碼 |
| 空白 | 未作答題 | 空白 |
| 複選 | 2 個、3 個選項塗黑 | 複選 |
| 淡色畫記 | 淺灰（約 35% 暗度） | 待確認（不得猜） |
| 擦除殘影 | 殘影＋新畫記；只有殘影 | 採新畫記；不得判為答案 |
| 打勾 | 打勾不塗滿 | 不得判為確定答案 |
| 傾斜拍攝 | 旋轉 12°＋梯形 15%；橫拿 90°；−80°＋梯形；倒放 180° | 逐題正確 |
| 低解析度 | 750×1000 照片 | 逐題正確 |
| 不同光照 | 亮度 100%→55% 漸層；斜向陰影 50%；偏暗＋陰影＋雜訊 | 逐題正確 |
| 反光 | 光斑蓋住第 3 題 | 第 3 題待確認、其他題不讀錯、警告 |
| 影像模糊 | σ=2 / 4 / 7 px | 正確無警告 / 正確有警告 / 拒收 |
| 部分超出畫面 | 右下角出框 | 拒收並提示入鏡 |
| 非答案卡 | 雜訊圖 | 拒收 |
| 重複掃描 | 同一張不同角度拍兩次 | 結果相同（指紋可比對） |

**合成測試通過不代表真實準確率。** 合成的鉛筆筆觸、光照、鏡頭失真都比真實情況單純。

## 2. 端到端測試（真實 Chromium，自動）

```powershell
npm run build
npx vite preview --port 4173      # 另開一個視窗
npm run synth
python tests/e2e/e2e_smoke.py     # 需要 Python playwright
```

流程：建立 20 題考試 → 快速輸入答案 → 答案卡頁面 → 等 OpenCV.js 在 Worker 中載入 → 一次上傳兩張合成照片 →
驗證 100 分、識別碼不符警告 → 人工把第 1 題改成 B（分數變 95）→ 儲存 → 第二張（倒放）同座號 → 驗證重複警告 → 取代 →
成績列表 → 下載 CSV 並驗證內容 → 上傳非答案卡圖片要求重拍 → 深色模式桌面版截圖。截圖在 `tests/e2e/screenshots/`。

這證明瀏覽器端整合（Worker、WebAssembly、IndexedDB、下載）可運作，**不是手機實機測試**。

## 3. 真實照片測試（人工＋自動統計）

這是唯一能回答「實際準不準」的測試。步驟：

1. 在 App 建立考試、列印答案卡（至少 10 張）。
2. 請不同人用 2B 鉛筆作答，刻意包含：正常、空白、複選、淡塗、擦掉重塗、擦掉不塗、打勾。
3. 用不同手機、在不同光線（日光燈、窗邊、黃光、桌燈陰影）、不同角度拍攝。每張也可以拍一張刻意失敗的（模糊、出框）。
4. **人工核對**每張的正確畫記，寫進 `tests/real/cases.json`（格式見 `tests/real/README.md`）。人工也無法確定的題目寫 `?`，不計入統計。
5. 執行 `npm run test:real`。

輸出：

- `report_<時間>.md`：全部與各情境的「正確／待確認／靜默錯誤」比例、逐張結果、座號與識別碼是否讀對。
- `errors_<時間>.jsonl`：每一筆不一致（照片、題號、預期、實得、四個選項的分數、原因）— 可追蹤、可回頭看照片。

判讀標準：

- **靜默錯誤**（引擎給了確定答案但錯）必須為 0；出現時看 jsonl 的分數，調整 `tests/real/params.json`（與 App「設定」同名欄位）後重跑。
- 待確認比例越低越好，但寧可多標待確認，也不要有靜默錯誤。
- 調好的參數再到 App 的「設定」輸入。
